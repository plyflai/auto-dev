# Capability: Architecture

## Enable When

- 新增或改变模块边界、接口面、共享抽象或跨平台结构。
- 广泛重构需要 expand-contract 或阶段迁移。
- 多个调用方依赖同一核心设计决定。
- 已有文件的职责混杂、依赖方向或测试边界已经阻碍当前交付，且安全拆分需要新的模块边界或多个调用方迁移。

## Hard Gates

- 用代码导航明确入口、调用方、消费方、对称路径与测试面。
- 区分模块、接口面、接缝与适配器；不以模糊“组件/服务”替代边界。
- 评估兼容窗口、迁移顺序和回退点。
- 新抽象需要稳定重复、清晰所有权、兼容边界、安全隔离或可测试性等证据；形式整洁本身不是依据。
- 文件长度只是调查信号；拆分必须改善职责归属、依赖方向、兼容边界或测试面，不能只追求更短文件。

## Behavior-Preserving Decomposition

当前交付确实需要拆解已有的混杂或过大文件时：

1. 先刻画现有职责、公共入口、外部副作用、调用方和测试面，并记录可证伪的 before 行为基线。
2. 只拆当前交付涉及的职责；优先提取具有稳定所有权和测试边界的纯逻辑、类型或适配器，不顺手清理无关旧债。
3. 通过原入口、facade 或兼容适配保持调用方式稳定；按可独立验证的批次迁移调用方，每批立即复验行为、分支和副作用。
4. contract 前用代码导航确认旧调用清零；没有等价证据时保留兼容入口并报告剩余迁移风险。
5. 防止假模块化：不得用只有转发职责的薄文件、循环依赖或需要跨多个文件才能理解一个简单动作来换取行数下降。

## Deliverables

- 当前与目标边界。
- 影响面和分阶段交付单元。
- 兼容、迁移、验证与回退策略。

## Completion

- 每个受影响调用方都有迁移或兼容结论。
- 每个阶段可独立验证和回退。
- 没有将无关重构混入当前需求。
- before/after 行为、公共入口和外部副作用保持等价，且新边界没有制造循环依赖或碎片模块。
