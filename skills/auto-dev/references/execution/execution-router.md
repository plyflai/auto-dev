# Execution Router

只消费已确认的最终需求回执和只读调查证据，选择 `Direct / Team Core`。

## Team 硬门槛

命中任一项进入 Team Core：

- 数据迁移、历史数据修改或删除、权限、认证、支付、安全、合规。
- 公共 API、Schema、协议、配置真相源或外部系统契约变化。
- 操作不可逆，或无法用局部 diff / scoped snapshot 可靠回退。
- 受保护分支，或范围内用户改动无法可靠保护。
- 多个独立用户结果、多个无关工作流，或确实需要并行专业角色。
- 新架构边界、共享抽象、跨平台分歧、广泛重构或发布协调。
- 运行诊断结论为 `foundation`，且需要新建跨模块日志层、稳定存储、保留策略、隐私边界或外部日志服务。
- 根因、目标调用链或可执行验证仍无法收敛。
- 用户明确要求 Team、Full 或完整治理。

新出现的业务决策先回 Requirement Intake；不能用 Team 绕过用户确认。

## Direct 默认条件

未命中 Team 硬门槛时默认 Direct，尤其是：

- 一个明确用户结果或缺陷复现。
- 一条连贯调用链或纵向用户流程。
- 可复用已有模式，无新公共契约或架构决策。
- 可局部回退，并有目标测试、构建、CLI 或 GUI 验证。
- 当前基模能独立定位、实现和验证。
- 已有项目级日志层可用，本轮只需为一条连贯运行路径补齐或验证诊断事件与读取入口。

文件数、代码行数、主观耗时和用户口头说“大 / 小”不单独决定档位。

## 动态升级

Direct 出现公共契约、数据、安全、不可逆、发布协调、跨无关系统、运行诊断基础设施扩大为共享边界、根因失焦或连续两轮未恢复 Green 时升级 Team Core。目标不变时复用已完成调查；目标变化时先 Requirement Diff。

## 路由回执

```text
🔥 auto-dev - [Direct / Team Core] 已激活
🧭 执行档位: [Direct / Team Core]
需求回执: [receipt_ref]
依据: [1-2 条决定性证据]
```

## 完成条件

- 只输出一个档位。
- 档位引用已确认且无 pending 的需求回执。
- Team 理由命中明确硬门槛；否则使用 Direct。
